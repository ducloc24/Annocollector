# Annocollector — Backend (FastAPI)

REST API built with FastAPI + SQLAlchemy 2 (async) + Alembic, running on
Supabase Postgres, using a layered architecture.

## Architecture

```
app/
├── main.py            # App factory, middleware, lifespan, error handlers
├── api/
│   ├── deps.py        # Shared dependencies (db session, services)
│   └── v1/
│       ├── router.py  # Aggregates endpoint routers
│       └── endpoints/ # HTTP layer: parse request → call service → return schema
├── core/              # Config, logging, exceptions
├── db/                # Base + engine/session factory
├── models/            # SQLAlchemy ORM models
├── schemas/           # Pydantic request/response models
├── repositories/      # Data access (queries only)
└── services/          # Business logic (raises domain errors)
```

Request flow: `endpoint → service → repository → database`.
The DB session is a request-scoped unit of work: it commits on success and
rolls back on any exception (see `app/db/session.py`).

## Setup

```bash
# from the repo root
uv sync --directory be          # creates/uses be/.venv
copy ..\.env.example ..\.env    # then fill SUPABASE_PASSWORD
uv run --directory be alembic upgrade head
uv run --directory be uvicorn app.main:app --reload --port 8000
```

- API: http://localhost:8000
- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc

## Configuration

Settings are read from two files (later wins): the repo-root `.env` (Supabase
credentials) and `be/.env` (backend overrides). Both are git-ignored.

```
SUPABASE_HOST=aws-0-eu-west-1.pooler.supabase.com
SUPABASE_PORT=6543              # transaction pooler used by the app
SUPABASE_MIGRATION_PORT=5432    # session pooler used by Alembic
SUPABASE_DB=postgres
SUPABASE_USER=postgres.<project-ref>
SUPABASE_PASSWORD=<your-database-password>
```

`app/core/config.py` builds the connection string at runtime:

- app → transaction pooler, `NullPool`, `statement_cache_size=0` (Supavisor
  does not support prepared statements across pooled connections);
- migrations → session pooler, where DDL is safe;
- `DATABASE_URL` / `MIGRATION_DATABASE_URL` override everything;
- with no Supabase settings it falls back to `be/app.db` (SQLite), which is
  what the tests use.

## Migrations

Alembic owns the schema. SQLAlchemy models do not create tables outside tests
(`AUTO_CREATE_TABLES=false`).

```bash
uv run alembic revision --autogenerate -m "describe change"
uv run alembic upgrade head
uv run alembic downgrade -1
uv run alembic current
uv run alembic history
```

Review every autogenerated migration: renames and drops need manual fixes.

## Endpoints

| Method | Path                 | Description              |
| ------ | -------------------- | ------------------------ |
| GET    | `/api/v1/health`     | Health check             |
| GET    | `/api/v1/items`      | List (paginated, search) |
| POST   | `/api/v1/items`      | Create                   |
| GET    | `/api/v1/items/{id}` | Detail                   |
| PATCH  | `/api/v1/items/{id}` | Partial update           |
| DELETE | `/api/v1/items/{id}` | Delete                   |

Errors use a consistent shape: `{"code": "...", "message": "...", "details": ...}`.
